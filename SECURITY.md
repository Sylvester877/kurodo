# Security Policy

## Reporting a vulnerability

Please do **not** open a public issue for a security vulnerability.

Use GitHub's private security reporting flow from the repository's **Security** tab. Include enough detail to reproduce the issue, the affected version, and any relevant logs or proof of concept that can be shared safely.

If private reporting is unavailable, contact the maintainer privately through the GitHub profile rather than publishing the vulnerability.

## What to include

- A clear description of the vulnerability
- Affected version(s)
- Reproduction steps
- Expected and actual behavior
- Potential impact
- A suggested fix, if known

## Response

Security reports will be reviewed as soon as practical. Please avoid publicly disclosing the issue until a fix or mitigation has been prepared.

## Scope

This policy covers security issues in the Kurōdo application, server, Electron integration, build configuration, and project infrastructure.
